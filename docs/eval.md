## 本轮变更（2026-09-13）

上一次首跑出现回退（第 1 轮 9/10、第 2 轮 8/10：Q8 两轮都直接拒答、Q10 一轮过一轮挂），本轮针对根因修复，题目与期望要点一字未改：

1. **事实问题强制先检索**：system prompt 增加铁律 1——凡是需要事实依据的问题必须先调 `search_journal`；"事实依据"明确包含日记里出现过的其他人、地点、事件（"个人 agent"不等于只能检索用户本人的条目），唯一例外是寒暄/改写/问自身能力。修复后 Q8 两轮日志都出现检索调用，答案命中"跳槽 / 字节 / 后端"（如"小李上个月跳槽去了字节跳动，做后端"）。
2. **无证据时否定前提**：system prompt 增加铁律 2——检索结果里没有问题预设的事实时，先否定前提本身（"日记和档案里都没有你养宠物的记录"），禁止"不知道它叫什么 / 不知道是什么时候 / 不知道跟谁去的"这类默认前提成立的句式，也不许用"它 / 他 / 她"回指预设对象。Q9、Q10 四轮全部是这种否定前提式拒答，且未编造日期、人名、宠物名。
3. **评测温度固定为 0**：`llm.chat_raw` 原先默认 `temperature=0.7`，即评测路径此前并非确定性解码；现新增 `llm.resolve_temperature`（显式入参 > `AGENT_LLM_TEMPERATURE` > 生产默认 0.7），`run_eval.py` 跑题前固定 `AGENT_LLM_TEMPERATURE=0` 并打印生效值。生产默认仍为 0.7，保留闲聊表达多样性。
4. **判定侧标点归一化 + 两处真实误判修复**：判定前统一归一连字符/减号族（en dash、em dash、数学减号、全角等）、全角数字字母与全角/不换行空格——修 Q2 的"期望月薪 10–15K"因 en dash 判挂；另修复 judge 两处真实误判：Q10 会漏判"日记里没提过…所以我不知道它叫什么"（接受错误前提却因前半句含否定词而通过），Q9 的同行人正则会把正确拒答"日记和档案里都没有你去日本旅游的记录"误判成编造同行人（改为逐小句判断，含否定词的小句跳过）。期望值、题目、检索参数均未改动。
